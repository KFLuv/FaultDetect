## 1. 背景与问题

### 1.1 用户

**主用户**：现场实施人员 / 驻场运维（非资深，会看浏览器、会重启服务，但没形成排查顺序）。
**次用户**：需要向上汇报的现场负责人（他要的是一份"能交上去"的结论）。

### 1.2 现状痛点

| # | 痛点 | 现象 |
|---|---|---|
| 1 | **不知道该先看什么** | 新人凭感觉试，反复重启服务、反复让人复现，半小时过去没有结论 |
| 2 | **老手经验不可传递** | 老手脑子里有一套顺序（先看服务活没活、再看状态码、再看前后端），但说不清、传不下去 |
| 3 | **转述即失真** | 用户说"网站打不开"，可能是前端、网关、数据库；**转述那一秒，事实就丢了** |
| 4 | **结论交不上去** | 说"我觉得是数据库问题"，领导问"依据呢"，答不出 |
| 5 | **内网不能外联** | 现场常无外网、且不允许把生产内容贴给公网大模型 |

### 1.3 问题陈述

> **现场排障的核心困难不是"不会修"，而是"不知道该问什么"。而通用对话式 AI 只能推理用户转述的事实。**
> 因此本产品要做的是：**自己去现场把事实拿回来，并让结论可被验证、可被复核。**

## 2. 目标与成功指标

### 2.1 产品目标

1. 输入一个故障 URL，**自动跑完 7 步排障 SOP**，产出一份可直接汇报的诊断报告。
2. 把结论拆成**观测层（实测）/ 归因层（推断）/ 结论层（建议）**，三层在界面上明显不同，**不给单一总分**。
3. **每条判断强制携带**「依据 + 反证条件 + 验证动作」。
4. 交付形态适配真实现场：**单文件 exe（免装 Java）/ 绿色版目录 / Docker**。

### 2.2 成功指标（含口径）

| 指标 | 口径定义 | 当前值 | 目标 |
|---|---|---|---|
| **观测层严格一致率** | 8 条真值用例中，系统实测类别与独立真值完全相同的条数 / 8 | **7/8 = 87.5%** | ≥ 7/8 并逐步消除粒度差异 |
| 知识库覆盖 | 内置故障场景数 / 状态码类数 | **132 / 59** | 持续补充 |
| 不可达场景出结论耗时 | 从点击"开始检测"到结果渲染完成 | 数秒级（HTTP/TCP 并行） | ≤ 10s |
| 结论可复核率 | 报告中带齐三要素（依据/反证/验证）的假设数 / 总假设数 | 100%（代码强制） | 保持 100% |
| **反指标** | 不产出"看起来像成功"的失败结果 | 外部调用异常一律 `degraded` | 保持 |

> **指标口径说明**：观测层一致率**不采用放宽后的判定**。SC_08（域名无法解析）真值为 `DNS_FAIL`、系统归入"连接被拒绝 / 网络不通"，**层次正确但粒度不足，如实计为不一致**，对外报 7/8。

## 3. 用户流程

### 3.1 主流程

```
打开程序（双击 exe，自动拉起服务 + 打开浏览器）
  → 输入故障 URL（可选：症状描述 / Token / Cookie / 超时）
  → 点击「开始检测」
      ├─ 第 0 步 URL 解析 + TCP 服务存活检测（与第 1 步并行）
      ├─ 第 1 步 HTTP 请求探测（状态码 / 响应头 / 响应体字节 / 耗时）
      ├─ 第 2 步 状态码归一化分析
      ├─ 第 3 步 响应特征提取 + 响应关键信息提取（业务码 / 异常类名 / 堆栈线索）
      ├─ 第 4 步 证据收集（接口记录 / 请求 / 响应）
      ├─ 第 5 步 分支判断（500 查日志 / 200 空数组查库 / 其他自动前后端隔离）
      └─ 第 6 步 差分隔离实验（只读对照矩阵，默认开启）
  → 结果区：三层结论 + 证据链 + 差分对照表 + 假设列表（含反证条件与验证动作）
  → 底部：本次故障的手动排查教学
  → 一键复制 3 段式汇报文本
```

### 3.2 异常分支（必须全部有出口）

| 分支 | 触发 | 行为 |
|---|---|---|
| URL 为空 / 缺主机名 | 输入校验 | 返回 400，不出报告 |
| 目标不可达（连接被拒 / 超时 / DNS 失败） | 第 0/1 步 | 直接给网络/服务层结论，**跳过差分实验**（各对照必然同样失败） |
| 未提供自定义请求头 | 输入 | CT_01 / CT_02 标为 `skip` 并写明原因 |
| 知识库未命中 | 匹配阶段 | 走**通用规则库**（28 条）产出多假设；仍未命中则由 LLM 层兜底 |
| LLM 未启用 / 不可达 / 返回非法 JSON | 增强阶段 | 记 `degraded` + 原因原样写入，**不抛异常、不影响既有结论** |

## 4. 范围

### 4.1 本期做

| 模块 | 内容 |
|---|---|
| 检测主链路 | 7 步 SOP；HTTP 与 TCP 并行 |
| 知识库 | 132 个故障场景 × 59 类状态码；10 个归属类别 |
| 通用推理层 | 28 条通用规则 + 7 条差分推导规则，每条强制带依据 / 反证条件 / 验证动作 |
| 差分隔离实验 | 只读对照矩阵：去 Authorization / 去全部自定义头 / 换 HEAD / 换协议 / 追加随机参数 / 原样重放 2 次 |
| 可信度自检 | 8 条真值用例，双实现交叉比对（真值 `HttpURLConnection`，被测 `HttpClient`） |
| 报告 | 3 段式（现象 → 排查过程 → 结论）；一键复制 |
| 教学 | 按本次状态码 + 归属动态生成"手动排障教学" + 7 步总纲 |
| 交付 | 单文件 exe（内嵌 jlink 精简 JRE）/ 绿色版目录 / Docker |
| 可选增强 | LLM 增强层，**默认关闭、按需触发** |

### 4.2 明确不做

| 不做 | 理由 |
|---|---|
| **不做自动修复 / 不执行任何写操作** | 差分实验直接打客户系统；写操作不可逆，风险不可控 |
| LLM 不默认开启 | 内网不可达；且把生产内容贴给公网模型本身违规 |
| 不做账号体系 / 多租户 | 离线单机工具，服务化不是本期目标 |
| 不做通用 AI 问答 | 通用对话只能推理转述的事实，与本产品定位冲突 |
| 不引入前端重型框架（Pinia / TS / UI 库） | 规模不需要，只会增加被追问的面 |

## 5. 功能需求

| 编号 | 功能 | 描述 | 触发 | 异常分支 | 验收标准 |
|---|---|---|---|---|---|
| FR-01 | URL 解析 | 提取协议 / 主机 / 端口 / 路径 | 提交检测 | 缺主机名 → 400 | 非法 URL 不出报告 |
| FR-02 | 服务存活检测 | TCP 连接目标端口 | 检测开始（默认开） | DNS 失败 / 拒绝 / 超时分别给可读原因 | 与 HTTP 探测并行，总耗时取二者最大值 |
| FR-03 | HTTP 探测 | 捕获状态码 / 响应头 / 响应体 / 耗时；**按字节接收后依 charset 解码，无声明时回退探测** | 检测开始 | 超时 / SSL / 无效 URL 各有独立文案 | GBK 响应中文不乱码（SC_04 / SC_05） |
| FR-04 | 状态码分析 | 归一化到知识库状态标识；未收录码按段位给通用解释 | 探测完成 | — | 132 个场景均可匹配 |
| FR-05 | 响应特征与关键信息 | 提取业务码 / 业务信息 / 异常类名 / 堆栈线索，**只呈现不参与打分** | 探测完成 | 非 JSON 响应走文本片段抽取 | 非 2xx 响应体的关键信息不被丢弃 |
| FR-06 | 场景匹配 | 状态码 + 响应特征 + 症状关键词打分 | FR-05 后 | 未命中走通用规则 | 置信度 ≥ 0.6 走高置信快速路径 |
| FR-07 | 通用假设推理 | 28 条通用规则产出多假设并排序，最多输出 5 条 | 匹配后 | 无假设则为空 | **每条假设必须带依据 + 反证条件 + 验证动作** |
| FR-08 | 差分隔离实验 | 对同一 URL 跑只读对照矩阵，用差异反推故障层次 | 检测后（默认开） | 基线无响应则整体跳过并说明 | **非 GET/HEAD 一律运行时抛错拒绝** |
| FR-09 | 三层结论与报告 | 观测 / 归因 / 结论分层展示；生成 3 段式汇报文本 | 推理完成 | — | 界面三层视觉可区分；不给单一总分 |
| FR-10 | 可信度自检 | 一键比对真值与实测，输出逐条明细与一致率 | 用户点击 | 自检服务自包含、跑完即关 | 8 条用例，严格口径 7/8，差异如实标注 |
| FR-11 | LLM 增强（可选） | 对结论做自然语言增强 / 库外故障兜底 | 用户显式勾选 | 六条异常路径全部降级 | **拔掉模型接口，产品仍能给出完整结论** |
| FR-12 | 历史与场景管理 | 检测历史持久化（SQLite）；自定义场景新增 | 用户操作 | 非法场景入参 → 400 | 容器重建 / 换位置不丢历史 |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 不可达场景数秒出结果；HTTP 与 TCP 并行；连接阶段超时独立控制（min(超时, 5s)） |
| 可用性 | 目标机**免装 Java**；单文件 exe 双击即用；托盘常驻 |
| 兼容性 | 强制 HTTP/1.1（避免 h2c 升级握手被网关吊住）；`jlink` 必须含 `jdk.crypto.ec` |
| 数据 | 数据落在固定目录（`%LOCALAPPDATA%`），升级 / 换位置不丢 |
| **安全** | 差分实验**只读**；非幂等方法运行时拒绝；全部对照串行执行 |
| 合规 | 默认本地运行，数据不出网 |
| 可维护 | 前后端依赖锁版本；知识库为 JSON，可人工维护 |

## 7. 数据与埋点

| 数据 | 用途 | 存储 |
|---|---|---|
| 检测历史（URL / 状态码 / 归属 / 命中场景 / 置信度 / 完整报告 JSON） | 历史回溯，离线可查 | SQLite `detect_history` |
| 自检结果（8 条用例的真值 / 实测 / 一致 / 耗时） | 可信度证据 | 接口实时返回，不落库 |
| 自定义场景 | 现场补充知识 | JSON 文件 |

**指标埋点**：观测层一致率、检测耗时、各步成功率由自检与历史记录推导，不引入额外埋点。

## 8. 风险与依赖

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | 观测层误判（如把 404 判成超时） | 后续推理再精致也是错误结论 | 内置独立真值自检；已知边界如实声明 |
| 2 | 差分实验对目标系统造成压力 | 影响客户系统 | 只读白名单 + 运行时拒绝 + 串行执行 + 基线复用 |
| 3 | 归因层本质是启发式规则 | 可能给出次优结论 | 三层分层展示 + 置信度 + 反证条件，交人工复核 |
| 4 | 入口门槛高（需用户自己找 URL 与 Token） | 目标用户被砍掉一半 | **已知最大缺口**，后续以浏览器书签脚本降低门槛 |
| 5 | 主链路 TLS 为 trust-all、无 SSRF 防护、无鉴权 | 服务化部署有风险 | 离线单机可接受；服务化前必须补齐 |

## 10. 已知边界（不掩盖）

1. **SC_08 为已声明的粒度差异**：系统未细分 DNS 失败与端口未监听，界面上黄字如实标注。
2. **200 状态码时归因依赖响应体特征**：若响应正常但业务异常（空数组 / 业务码藏在 body），观测层拿不到更多事实，需人工复核。
3. **三要素靠人工纪律，无断言机制**：`refute_if` / `verify_actions` 尚未加非空断言。
4. **Python 版（v1）能力不对等**：无自检、无差分实验、无通用假设引擎、无 LLM 层，不能声称"两版功能相同"。

## 11. 后续迭代（按优先级）

| # | 迭代项 | 价值 |
|---|---|---|
| 1 | **浏览器书签脚本**：在故障页点一下自动抓 URL + 失败请求 + 控制台错误 | 直接降低入口门槛，补齐最大缺口 |
| 2 | 给三要素加**启动期非空断言** | 把"人工纪律"变成"机制约束" |
| 3 | 7 步流程**逐步实时展示**状态与耗时 | 用户知道在等什么 |
| 4 | 结论增加**证据等级字段** | 弱证据不允许给高置信度 |
| 5 | 补**SSRF 防护与鉴权** | 服务化部署前置条件 |
