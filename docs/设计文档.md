## 第一章 系统概述

### 1.1 设计目标

本系统的设计目标**不是"自动修故障"**，而是：

> **让现场人员给出的判断"可被验证、可被复核"。**

围绕这个目标，系统设计遵循四条原则：

| # | 原则 | 落地方式 |
|---|---|---|
| 1 | **结论可证伪** | 每条判断同时给出「依据 + 反证条件 + 验证动作」 |
| 2 | **结论分层可信** | 观测层（实测）/ 归因层（推断）/ 结论层（建议）三层分开呈现 |
| 3 | **验证独立于生成方** | 自检的真值走一套独立实现，不用被测实现验证自己 |
| 4 | **零假成功** | 外部调用异常一律降级，绝不产出看起来像成功的产物 |

### 1.2 设计约束

| 约束 | 来源 | 对设计的影响 |
|---|---|---|
| **现场机器装不了 Docker** | 客户环境（内网、无管理员权限、可能没装 Java） | 必须提供**单文件 exe**（内嵌精简 JRE）形态 |
| **内网离线** | 客户安全要求 | 模型层**必须默认关闭**，且拔掉模型接口仍能出完整结论 |
| **不能影响客户系统** | 差分实验会真的打目标系统 | 只允许**只读请求**，写操作**运行时拒绝** |
| **不可信输入** | 系统处理的对象就是故障现场 | 响应体/堆栈/用户描述都可能携带指令，属于攻击面 |

### 1.3 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| **后端** | Java 11 + Spring Boot 2.7.18 | 与客户既有系统技术栈一致，便于现场维护 |
| **前端** | Vue 3 + Vite 5 | 轻量、构建快、单文件部署友好 |
| **知识库** | JSON（`scenarios.json` / `status_codes.json`） | 无需数据库即可启动，便于离线交付与人工维护 |
| **历史记录** | SQLite（`fault_detect.db`） | 单文件、免安装、可随程序携带 |
| **部署** | jlink 精简 JRE + 单文件 exe / Docker | 适配三种现场环境 |

## 第三章 数据设计

### 3.1 知识库数据模型

#### 3.1.1 故障场景（Scenario）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | String | 场景编号，如 `SCN_001` |
| `name` | String | 场景名称，如"后端服务未启动" |
| `http_codes` | List\<String\> | 关联状态码，如 `["pending"]` |
| `response_patterns` | List\<String\> | 响应特征关键词，如 `["no response","timeout","超时"]` |
| `ui_symptoms` | List\<String\> | 用户侧症状，如 `["转圈","无响应","打不开"]` |
| `root_cause` | String | 归属类别 key（对应 10 类标签） |
| `conclusion` | String | 结论文案 |
| `evidence` | List\<String\> | **依据**（含 `{host}` / `{port}` 占位符） |
| `solution` | List\<String\> | 修复建议 |
| `probability` | double | 先验概率 0.35–1.0 |
| `priority` | String | 优先级：高 / 中 / 低 |
| `custom` | Boolean | 仅自定义场景输出（内置场景无此键） |

#### 3.1.2 状态码（StatusCode）

| 字段 | 说明 |
|---|---|
| `code` | 状态码标识，如 `pending` |
| `name` | 中文名，如"无响应 / 超时" |
| `category` | 归类，如"无响应" |
| `problem_category` | 可能的问题大类，如 `["服务","网络"]` |
| `next_step` | **下一步动作指引** |
| `description` | 说明 |
| `memory` | 记忆口诀，如"空白/pending → 网络/服务问题，先做第 0 步" |
| `typical` | 典型原因列表 |

### 3.2 业务数据模型

#### 3.2.1 检测历史（`detect_history`）

```sql
CREATE TABLE IF NOT EXISTS detect_history (
    id            TEXT PRIMARY KEY,   -- 12 位随机串
    ts            TEXT,               -- yyyy-MM-dd HH:mm:ss
    url           TEXT,               -- 被检测的 URL
    status_code   TEXT,               -- 归一化后的状态标识
    root_cause    TEXT,               -- 归属类别中文名
    scenario_name TEXT,               -- 命中场景名
    confidence    REAL,               -- 置信度 0–1
    report        TEXT                -- 完整报告 JSON
);
```

> **设计取舍**：把完整报告 JSON 冗余存一份（`report`），是为了**历史记录可离线回溯**，不依赖知识库当前版本。代价是存储冗余。

## 第四章 核心流程设计

### 4.1 7 步排障 SOP

| 步 | 动作 | 实现 | 说明 |
|---|---|---|---|
| **0** | URL 解析 + TCP 存活 | `parseUrl()` / `tcpCheck()` | **与 HTTP 探测并行**，不可达场景几秒出结果 |
| **1** | HTTP 请求探测 | `httpProbe()` | 捕获状态码 / 耗时 / 原始字节 / 响应头 |
| **2** | 编码解码 | `decodeBody()` | **按字节接收 + 依 charset 解码**（含回退探测） |
| **3** | 状态码归一化 | `normalizeStatus()` | 映射到知识库的 59 类状态标识 |
| **4** | 特征提取 | `extractFeatures()` | 关键词匹配，产出 `MatchResult` | 
| **5** | 证据收集 | `extractKeyInfo()` | 固定收 3 样证据 |
| **6** | 分支判断 + 自动隔离 | `autoIsolation()` | 500 查日志 / 200 空数组查数据库 |

**前置差分子流程**（第 6 步之后按需触发）：`ContrastProbe.run()` 生成只读对照矩阵。

### 4.2 差分隔离实验设计

**目的**：主动生成"用户没想到的对照"，用**差异**反推根因落在哪一层。

**只读对照矩阵：**

| 对照维度 | 做法 |
|---|---|
| 去认证头 | 去掉 Authorization 后重放，看响应是否变化 |
| 换方法 | GET → HEAD |
| 换协议 | http → https |
| 追加随机参数 | 排除缓存命中 |
| 原样重放 | 判断是否稳定复现 |

**安全设计（关键）：**

```java
// 白名单
SAFE_METHODS = {"GET", "HEAD"}

// 且不止白名单 —— 运行时硬性拒绝
assertSafeMethod(method);
// 非只读方法直接抛 IllegalStateException
```

> **为什么不用单纯白名单**：白名单只挡"名单外"的方法；**运行时抛错能在任何调用路径上兜住**，更难绕过。

### 4.3 独立真值自检设计

**设计原则：不允许用生成方自己验证自己。**

| 角色 | 实现 | 独立性说明 |
|---|---|---|
| **真值** | `java.net.HttpURLConnection`（显式 `Proxy.NO_PROXY`） | 与主检测链路**完全独立的两套 JDK 实现** |
| **被测** | `java.net.http.HttpClient`（已固定 HTTP/1.1） | 主链路实际使用的实现 |

**测试服务自包含设计：**

```
内置裸 ServerSocket
  · 端口随机（ServerSocket(0)）
  · 仅绑定 127.0.0.1（不对外暴露）
  · 自检结束即关闭
  · 全部只读 GET 请求
  · 单条用例探测超时 3 秒（挂起用例靠它收敛）
```

**8 条用例设计：**

| 用例 | 场景 | 期望 | 覆盖点 |
|---|---|---|---|
| SC_01 | 本地 200（UTF-8 中文响应） | 200 | 基础通路 |
| SC_02 | 本地 404 | 404 | 客户端错误 |
| SC_03 | 本地 500（含异常类名） | 500 | 服务端错误 |
| SC_04 | GBK 响应（**声明** charset） | 200 + 中文未乱码 | **编码解码路径 A** |
| SC_05 | GBK 响应（**未声明** charset） | 200 + 中文未乱码 | **编码解码路径 B（回退探测）** |
| SC_06 | 服务端挂起不响应 | TIMEOUT | 超时判定 |
| SC_07 | 端口无人监听 | CONN_REFUSED | 连接层判定 |
| SC_08 | 域名无法解析 | DNS_FAIL | **粒度边界（已知差异）** |

### 4.4 LLM 增强层设计

**定位（关键）**：**不参与结论生成**，只对已经确定的规则结论做自然语言解释与措辞增强。

> **这个定位是刻意的 —— 结论的可靠性不能依赖模型。**

| 设计项 | 做法 |
|---|---|
| **默认状态** | 关闭（`faultdetect.llm.enabled:false`） |
| **触发方式** | 按需触发 |
| **状态机** | `STATUS_DISABLED` / `STATUS_OK` / `STATUS_DEGRADED` |
| **异常处理** | 6 条异常路径全部降级为规则结论 |
| **降级语义** | 状态记为 `degraded`，原因原样写进结果；**不抛异常、不阻塞、不影响既有结论** |
| **安全默认** | `insecure-tls` 默认 `false`（保持安全默认值） |

**6 条异常路径：**

| # | 路径 | 处理 |
|---|---|---|
| 1 | 非 2xx 响应 | 降级 |
| 2 | 连接失败 / 超时 / DNS 失败 / 证书错误 | 降级 |
| 3 | 返回内容解析异常 | 降级 |
| 4 | 返回的不是合法 JSON 对象 | 降级 |
| 5 | 缺 `conclusion` 字段 | 降级 |
| 6 | 找不到预期的 `choices` 结构 | 降级 |

**验收标准**：**拔掉模型接口，全流程仍能产出完整报告。**

### 5.2 参数安全校验

| 校验项 | 规则 | 目的 |
|---|---|---|
| 请求头名 | `^[A-Za-z0-9-]+$` | 防非法头名注入 |
| 请求头值 | **拒绝含 `\r` 或 `\n`** | **防 HTTP 头注入（CRLF）** |

> **这条校验最容易被忽略** —— 在"允许用户自定义请求头"的工具里，头注入是直接的攻击面。

## 第六章 风险分级与边界控制

### 6.1 风险分级

| 级别 | 动作类型 | 系统自主权 |
|---|---|---|
| **L0** | 读取状态码 / 耗时 / 响应体 | ✅ 自动执行 |
| **L1** | 差分对照实验（**只读重放**） | ✅ 自动执行 |
| **L2** | 对目标发**非只读请求** | ❌ **运行时拒绝**（比"必须确认"更严格） |
| **L3** | 新增/修改知识库、清空历史 | ⚠️ **当前无确认机制（已知缺口）** |
| **—** | 调用外部大模型 | ✅ 默认关闭，按需开启 |

### 6.2 边界控制实现

| 控制点 | 实现 |
|---|---|
| 只读白名单 | `SAFE_METHODS = {"GET","HEAD"}` |
| **运行时强制** | 非只读方法**直接抛异常**，不依赖调用方自觉 |
| 自检服务隔离 | 仅绑 `127.0.0.1`、随机端口、跑完即关 |
| 请求头注入防护 | 拒绝含 CRLF 的头值 |

### 6.3 已知安全缺口（**如实标注**）

| # | 缺口 | 影响 | 修复方向 |
|---|---|---|---|
| 1 | 主检测链路 TLS 为 **trust-all** | 中间人风险 | 提供服务端证书校验开关 |
| 2 | **无 SSRF 防护** | 无内网/回环地址黑名单，理论上可探测内网 | 加黑名单 + 地址白名单 |
| 3 | **无鉴权** | 服务暴露即人人可用 | 离线单机场景可接受；**服务化前必须补** |
| 4 | **LLM 层输入未包裹** | 响应体/堆栈/用户描述可能携带指令（Prompt 注入面） | 不可信内容包裹 + 出站脱敏 |
| 5 | 三态字段**无非空断言** | "每条必带反证条件"靠人工纪律 | 加断言，缺字段在启动期报错 |

## 第七章 部署设计

### 7.1 三种交付形态

| 形态 | 适配环境 | 构建方式 |
|---|---|---|
| **单文件 exe**（主推） | 现场机器**装不了 Docker**、无管理员权限、**甚至没装 Java** | jlink 精简 JRE + 内嵌打包 |
| **标准版目录** | 可自行维护 Java 环境 | jar + runtime 目录 |
| **Docker** | 有运维能力的服务器 | 多阶段构建 |

**三种形态功能完全一致**，区别只在适配环境。

### 7.2 踩过的坑（重要）

> **jlink 打包精简 JRE 时必须显式带上 `jdk.crypto.ec` 模块。**
> **少这一个模块，HTTPS 握手直接失败。**

**为什么这个坑值得记录**：本地开发使用完整 JDK，**所有模块都在，永远不会暴露这个问题**。只有打完包在真机上试才会发现。

### 7.3 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows / Linux |
| Java | 无需安装（exe 内嵌）；标准版需 JRE 11+ |
| 数据库 | 无需安装（SQLite 单文件） |
| 网络 | 可离线运行；模型增强层需可达 |

## 第八章 评测设计

### 8.1 评测集构成

| 项 | 值 |
|---|---|
| 场景库 | **132 个故障场景** |
| 状态码库 | **59 类状态码** |
| 归属类别 | **10 类** |
| 构建方式 | 从三份材料提炼基础（11 场景练习集、实施助理版指南、标准排障 SOP），再按真实故障类型补充 |

### 8.2 评测方式

| 评测类型 | 做法 | 覆盖范围 |
|---|---|---|
| **独立真值自检** | 8 条用例，双实现交叉比对 | **观测层准确性**（核心链路） |
| **Badcase 闭环** | 抽取 → 归因 → 修复 → 回归 | 现场误判问题 |
| **场景覆盖** | 10 类归属 / 132 场景 | 知识库覆盖度 |

### 8.3 结果口径（**必须说清**）

| 口径 | 值 | 说明 |
|---|---|---|
| 界面/接口对外报 | `passed: 8 / total: 8`，`consistency: 100.0` | ⚠️ **这是放宽判定标准后的结果** |
| **如实口径** | **7 / 8 一致 + 1 条已声明的粒度差异** | ✅ **对外应使用这个数字** |

**为什么两者不同**：判定函数对 `SC_08` 做了显式豁免 ——

```java
// DNS 解析失败：当前实现归类为「连接被拒绝」，层次判断正确但粒度不足，
// 为避免把已知的表达粒度差异算作不一致，这里按「可达性失败」同族计入，
// 并在 note 中如实标注，不掩盖该差异。
if (T_DNS_FAIL.equals(truth)) {
    return T_CONN_REFUSED.equals(actual);
}
```

**SC_08 实测数据**（来自真实运行）：

| 字段 | 值 |
|---|---|
| 真值 | `DNS_FAIL` |
| 系统实际判定 | `CONN_REFUSED` |
| 是否一致（原始） | ❌ **不一致** |
| 是否一致（豁免后） | ✅ 计为一致 |
| note | *"（已知粒度差异：真值为 DNS 解析失败，系统归类到「连接被拒绝 / 网络不通」，故障层次判断正确，但未细分 DNS 与端口两类原因）"* |

> **结论**：`DNS 解析失败` 与 `端口未监听` 在系统里被归成了同一类。**层次正确、粒度不足。**
> 对外报 **7/8** 并说明这一条差在哪 —— **放宽标准算出来的 100% 不能当作证据。**

详细的评测明细见 [`评测报告.md`](评测报告.md)。
