# FaultDetect 能力与适配边界

更新日期：2026-11-08

## 一句话定位

FaultDetect 是一个面向**非技术业务人员和客户对接人员**的 Web HTTP 现场第一响应工作台：

> 当开发、运维或技术人员无法第一时间到场时，在用户授权下自动采集一次真实操作触发的失败请求，执行只读检测与分层归因，并生成可以交给研发继续处理的证据和交接包。

它不是自动修复工具，也不是仅凭一个 URL 就能判断所有根因的诊断器。

## 现在能拿来干什么

### 1. 现场采集

- 在 FaultDetect 主窗口内打开 Web 系统；
- 正常登录后开启一次问题记录；
- 点击出问题的业务按钮；
- 自动关联按钮文字、发生时间和它触发的请求；
- 记录期间的 XHR / Fetch、页面导航与失败主文档请求；
- 自动带入 Cookie、Authorization 和自定义认证头；
- 记录前和记录后的无关请求不进入候选。

### 2. 只读自动检测

- 手动输入 URL，或从采集候选选择请求；
- 解析 URL、域名、端口、路径和查询参数；
- 执行 TCP 服务存活检查；
- 发起 HTTP / HTTPS 只读探测；
- 分析状态码、响应头、响应体、编码和耗时；
- 提取业务码、异常类、堆栈线索和错误关键词；
- 执行去认证头、去自定义头、Head、协议、随机参数等差分对照；
- 输出多条假设、支持证据、反证条件和下一步验证动作。

### 3. 不可重放请求的证据采集

- POST、PUT、PATCH、DELETE 不会自动重放；
- 可以生成失败请求快照；
- 快照包含方法、URL、状态码、响应体、耗时和 Trace ID；
- 请求体默认不采集，用户确认后才读取；
- Password、Token、Secret、API Key、手机号和证件号会脱敏；
- 快照和交接包用于研发继续定位，不代表自动完成根因确认。
- 采集列表最多保留最近 80 条候选请求；
- 响应体和请求体预览最多保留 12,000 字符；
- 二进制文件、上传文件内容和流式响应不做完整内容分析；
- 内置采集自动带入的可选请求头以 `Authorization`、`Cookie` 和 `X-*` 为主；
- 手动输入模式可以填写合法自定义请求头，但会拒绝 CRLF 换行注入。

### 4. 认证与上下文

- Cookie；
- Authorization；
- Bearer、Basic、Token、JWT；
- 自定义认证前缀；
- 自定义请求头；
- URL 中的 token 查询参数；
- 登录态、权限、会话过期和 Trace ID。

Trace ID 目前从常见请求头和 JSON 字段提取，能够复制并套用本地配置的日志 URL 模板，但不会自动登录或调用 Jaeger、SkyWalking、ELK、SLS 等日志平台。

### 5. 结果与跟进

- 观测层、归因层和结论层分开展示；
- 生成现象、排查过程、结论三段式汇报；
- 复制研发交接包；
- 复制 Trace ID 或打开本地日志 URL 模板；
- 历史任务记录；
- 负责人、备注、状态和关闭原因；
- JSON / Markdown 导出；
- 重新检测和单条删除；
- 未知场景模式；
- 用户确认根因后归档为自定义场景；
- 重复或并发归档返回同一场景，不重复创建。

## 能辅助识别的主要问题范围

### 网络与连通性

- DNS 解析失败；
- 连接拒绝；
- 超时与断网；
- 防火墙、安全设备或企业网络准入问题；
- HTTP 版本不兼容；
- 内置业务窗口页面加载时的 TLS / 证书兼容提示；
- 代理、VPN 或网关导致的访问异常。

注意：

- 后端对 API 的主动探测当前使用 trust-all TLS 上下文，因此不能把“接口探测成功”当成证书链已验证；
- 后端主动探测不走系统代理，代理场景以内置窗口能否访问为准；
- 后端主动探测不跟随 HTTP 重定向，只观察 3xx 响应。

### HTTP 与协议

- 2xx、3xx、4xx、5xx；
- 未收录状态码；
- 观察重定向、循环和错误跳转线索，但不自动跟随跳转链；
- 缓存、ETag、304、412；
- 上传大小、请求体、URI 长度和请求头限制；
- Content-Type、响应格式与内容协商；
- GBK / UTF-8 响应解码与中文乱码。

### 认证与权限

- 未登录；
- Token 过期、格式错误或缺失；
- 登录接口失败；
- Cookie / 代理会话失效；
- 401、403；
- RBAC 配置错误；
- 数据权限过滤；
- 菜单隐藏但接口仍可调用；
- 业务码表示登录失效或权限不足。

### 接口与前后端契约

- 接口不存在、被删除或旧版本残留；
- 请求方法错误；
- 参数缺失、格式错误、类型错误和字段名不匹配；
- JSON 解析失败；
- 后端未实现或返回格式不支持；
- 成功但无提示、列表不刷新、跳转错误；
- 业务异常但前端只看 HTTP 状态码；
- 重复提交；
- 前后端对空数据、错误码和业务信封处理不一致。

### 服务、网关与性能

- 后端未启动、崩溃、维护或卡死；
- 502、503、504；
- Nginx、网关、路由和代理配置；
- 限流、过载和 IP 封禁；
- 慢 SQL、第三方接口超时、连接池耗尽；
- CORS 和预检请求；
- WAF、CDN 或安全设备拦截；
- 长任务被网关提前切断。

### 数据库与业务数据

- 数据库连接失败；
- 表不存在或查询无数据；
- SQL 异常；
- 唯一约束冲突；
- 单行查询返回多行；
- 并发锁、乐观锁和重复提交；
- 付费功能未开通；
- 合规、审计或地域策略拦截；
- 业务码成功但数据为空。

### 前端与浏览器表现

- 前端渲染失败；
- 字段映射错误；
- 成功响应未展示；
- 创建后列表不刷新；
- 异步任务无状态；
- 下载、分片和断点续传错误；
- 静态资源 404；
- 缓存导致旧数据；
- 浏览器 CORS / 混合内容 / 安全策略问题，需结合浏览器现场信息复核。

## 当前内置知识库

- 132 个故障场景；
- 59 个状态码解释；
- 10 个问题归属类别；
- 28 条通用假设规则；
- 7 条差分推导规则；
- 8 条观测层双实现真值用例；
- 10 条归因层固定事实用例。

教学页会动态列出当前知识库的全部 132 个场景名称。场景名称来自：

`java-backend/src/main/resources/knowledge/scenarios.json`

新增自定义场景后，教学页的完整清单会同步显示新增项。

### 评测口径

- 观测层：8 条双实现真值用例，严格口径 `7/8`；
- 归因层：10 条固定事实用例，当前 `10/10`；
- 132 个场景是知识库覆盖目录，不代表 132 个场景都已完成真实企业逐条验证；
- 归因层通过不等于最终根因已经确认，仍需按报告中的验证动作复核；
- UI、API、桌面采集、历史、导出和恢复通过，只证明工程流程可运行，不证明所有真实故障都能一次定位。

## 适配方式

| 方式 | 支持程度 | 说明 |
| --- | --- | --- |
| 手动输入 GET / HEAD URL | 直接支持 | 可做服务、HTTP、响应、差分和归因 |
| 内置窗口采集 GET / HEAD | 完整支持 | 自动关联按钮、请求和登录态 |
| 内置窗口采集 POST / PUT / PATCH / DELETE | 快照支持 | 不自动重放，保留脱敏证据和交接信息 |
| 外部 Chrome / Edge 已打开页面 | 不支持 | 不会监听原浏览器会话 |
| 手机 App / 原生客户端 | 不支持 | 需要 SDK、代理或原生网络采集 |
| WebSocket / SSE | 不支持完整诊断 | 当前只覆盖 HTTP 请求和页面导航 |
| 文件上传 / 多步骤事务 | 受限 | 可保留快照，不能自动重放完整事务 |
| SSO 弹窗 / MFA | 有条件支持 | 弹窗可打开，极端企业策略需现场验证 |
| VPN / 代理 / 客户端证书 | 环境依赖 | 当前电脑能访问并完成认证时才可用 |

## 部署与数据边界

- 当前正式交付形态：Windows x64 便携 EXE；
- 标准 JAR 可用于本地开发或受控环境，不作为普通现场用户的首选；
- Docker 文件保留用于构建研究，不是 v1.3.8 的正式支持形态；
- API 只监听 `127.0.0.1`，并再次校验回环地址；
- 当前是单机单用户模式，不支持局域网多人协作；
- 历史数据库和自定义场景保存在本地数据目录；
- 检测历史默认保留 180 天；
- 采集会话使用独立内存 Session，关闭后不保留登录 Cookie；
- 请求体证据只用于当前进程和本次交接，不进入历史数据库；
- 当前没有代码签名、自动更新、崩溃上报和远程运维通道；
- Windows 可能对未签名便携 EXE 显示 SmartScreen 提示。

## 已知安全风险

- 后端主动探测为 trust-all TLS，无法作为证书链验证工具；
- 当前没有完整的 SSRF 地址白名单，只适合在授权目标上使用；
- 本机服务依赖回环地址隔离，不具备多用户鉴权能力；
- 敏感字段脱敏是正则启发式，不能保证覆盖所有自定义密钥格式；
- 可选的 LLM 增强会处理响应体和故障描述，存在不可信输入与 Prompt 注入面；
- 现场导出和交接前仍需人工检查是否包含业务敏感信息。

## 明确不能直接做到

- 不自动修复问题；
- 不自动提交、删除或修改目标系统；
- 不自动处理一次性验证码、支付和不可逆业务动作；
- 不替代服务端日志、APM、数据库审计和抓包；
- 不提供压测、并发压测、故障注入和容量评估；
- 不支持手机 App、Windows 原生客户端和系统级全部流量；
- 不完整支持 WebSocket、SSE 和长连接消息诊断；
- 不监听用户原来的浏览器窗口；
- 不保证每个问题一次定位最终根因。

## 最准确的产品表述

> FaultDetect 能自动完成 Web HTTP 问题的第一响应、证据采集、只读探测、分层归因和研发交接。
> 它解决的是“现场先把事实拿回来，并知道下一步查什么”，不是“所有系统都能一键自动修好”。
