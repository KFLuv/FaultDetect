## 三个最值得看的点

### 1️⃣ 结果页设计：三层可信度（[原型](原型/02-结果页-三层结论.png)）

**AI 产品最常见的坑：把推断当事实展示。**

所以我把结论拆成三层，**在界面上长得明显不一样**：
- **观测层**（我实测到的，高可信）
- **归因层**（我推的，启发式）
- **结论层**（我的建议）

而且**不给单一总分** —— 一个总分是最容易被误读的东西。

### 2️⃣ 口径诚实：对外报 7/8，不是 8/8（[评测报告](评测报告.md)）

接口自己返回的是：

```json
{ "total": 8, "passed": 8, "consistency": 100.0 }
```

**但我改成对外报 7/8。** 因为那唯一一条不一致（`SC_08`），是**我自己在判定标准里把它归成了"同类"** 才算过的：

| | |
|---|---|
| 真值 | `DNS_FAIL`（域名解析失败） |
| 系统判为 | `CONN_REFUSED`（连接被拒绝） |
| 层次 | ✅ 都属"网络不可达" |
| 粒度 | ❌ 没细分 DNS 与端口 —— **而这两类排查方向完全不同** |

**放宽标准算出来的 100% 不能当证据。**

### 3️⃣ 边界控制：写操作运行时直接拒绝（[产品文档](产品文档.md) 决策 6）

差分实验会真的去打目标系统，所以：

> 不只做只读白名单，**非只读方法直接抛异常拒绝** —— 白名单只挡"名单外"的，运行时抛错挡的是**任何绕过路径**。

## 我在这个产品上还没做到的

> 一个只讲优点的作品集，可信度反而更低。所以这一节我主动写。

| # | 缺什么 | 影响 |
|---|---|---|
| **1** | **入门门槛太高，等于砍掉一半目标用户** | 用户要先用开发者工具找到接口地址和 Token —— 而"不知道该看哪里"恰恰是这个产品要解决的痛点。**会翻开发者工具的人，离直接问 AI 只差一步。** 下一步要补：浏览器书签脚本 |
| **2** | **三态判定靠人工纪律** | `refute_if` / `verify_actions` 字段没有非空断言。应该加断言，让"缺反证条件"变成**启动期错误** |
| **3** | **安全没做收尾** | TLS trust-all、无 SSRF 防护（无内网/回环黑名单）、无鉴权。离线单机可接受，**服务化部署前必须补** |
| **4** | **LLM 层输入未包裹** | 响应体/堆栈/用户描述可能携带指令（**Prompt 注入面**）—— 已识别，未修复 |
| **5** | **SC_08 粒度不足** | `DNS_FAIL` 与 `CONN_REFUSED` 未细分，已在评测报告中声明并给出修复方向 |
