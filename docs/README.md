## 三个最值得看的点

### 1️⃣ 结果页设计：三层可信度（[原型](原型/02-结果页-三层结论.png)）

**AI 产品最常见的坑：把推断当事实展示。**

所以我把结论拆成三层，**在界面上长得明显不一样**：
- **观测层**（我实测到的，高可信）
- **归因层**（我推的，启发式）
- **结论层**（我的建议）

而且**不给单一总分** —— 一个总分是最容易被误读的东西。

### 2️⃣ 口径诚实：对外报 7/8，不是 8/8（[评测报告](评测报告.md)）

当前对外严格口径是 **7/8**。那唯一一条不一致（`SC_08`）是 **DNS 解析失败** 与 **连接拒绝** 未细分：

| | |
|---|---|
| 真值 | `DNS_FAIL`（域名解析失败） |
| 系统判为 | `CONN_REFUSED`（连接被拒绝） |
| 层次 | ✅ 都属"网络不可达" |
| 粒度 | ❌ 没细分 DNS 与端口 —— **而这两类排查方向完全不同** |

**放宽标准算出来的 100% 不能当证据。**

### 3️⃣ 边界控制：写操作运行时直接拒绝（[产品文档](产品文档.md) 决策 6）

差分实验会真的去打目标系统，所以：

> 不只做只读白名单，**非只读方法直接抛异常拒绝** —— 白名单只挡"名单外"的，运行时抛错挡的是**任何绕过路径**。

## 当前仍需补齐

| # | 缺什么 | 影响 |
|---|---|---|
| **1** | 真实企业环境验证不足 | SSO、MFA、VPN、代理、客户端证书仍需现场样本 |
| **2** | 证书与网络边界 | 主动探测为 TLS trust-all，不走系统代理，不跟随重定向 |
| **3** | SSRF 与多用户边界 | 当前仅适合授权目标的本机单用户模式 |
| **4** | 日志平台自动适配 | 现在提供 Trace、复制和 URL 模板，不自动登录 Jaeger / ELK / SLS |
| **5** | 正式工程交付 | 暂无代码签名、自动更新和崩溃上报 |
| **6** | 132 场景真实回归 | 场景目录完整，但不等于 132 条都已在真实企业逐条验证 |
| **7** | SC_08 粒度不足 | `DNS_FAIL` 与 `CONN_REFUSED` 仍未细分 |
