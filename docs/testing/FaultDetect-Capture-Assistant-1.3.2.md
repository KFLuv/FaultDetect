# FaultDetect v1.3.2 内置业务系统采集验证

日期：2026-11-06
验收对象：`FaultDetect-1.3.2-portable.exe`

## 目标

验证业务人员不需要使用 F12，也能在桌面端完成“打开业务系统、记录一次问题、选择请求、执行诊断”的完整流程。

## 测试流程

1. 在 FaultDetect 主窗口输入本地模拟业务系统地址。
2. 确认应用打开独立的内置业务系统窗口。
3. 页面在待机状态先发起一次正常请求。
4. 点击“开始记录本次问题”。
5. 在业务系统里点击出错操作，发起带 Authorization、Cookie 和自定义请求头的 GET 500。
6. 回到 FaultDetect，确认只出现开始记录后的失败请求。
7. 勾选授权确认，选择“使用并检测”。
8. 打开左侧“使用教学”页，使用内置演示重复正常、失败和提交类请求。

## 结果

- 待机阶段正常请求未进入候选列表。
- 录制开关工作正常。
- 失败请求识别为 `GET /error` 和 `HTTP 500`。
- 页面没有显示 Token 或 Cookie。
- 自动检测时 Authorization、Cookie 和自定义 `X-Tenant` 请求头均正确转发。
- 诊断报告返回 500，报告内容不包含真实凭证。
- 浏览器与移动布局回归无横向溢出，运行时错误为 0。
- 内置教学页可以打开演示系统；GET 失败请求可以检测，POST 请求只显示“复制交接信息”。

## 方案边界

- 当前只捕获在 FaultDetect 内置窗口打开的 Web 系统。
- 用户原来 Chrome / Edge 中的请求需要浏览器扩展。
- 原生桌面或手机 App 需要 SDK、埋点或网络代理接入。
- 只有 GET 请求允许自动重放；提交类请求只提供脱敏交接信息。
